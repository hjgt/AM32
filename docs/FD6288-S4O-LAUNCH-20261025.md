# S4O: one-sector startup launch-vector comparison

## Captured evidence, not a rotor-position measurement

S4N-STATS capture-first.bin.json and capture-failure.bin.json in
hardware-backups/S4N-STATS-flash-sAbtXN/ contain trial2 success and trial8 failure.
Success trial2: first acquisition sector starts60.077ms, directed margin -11..9,
first qualified edge60.820ms, software handoff106.175ms. Failure trial8: first
sector60.091..90.123ms,721 samples, directed margin -3..147, first116/last-3,
702 unarmed decisions, no observed pre-side below-8. No invalid or early rejects.
Subsequent failed sectors often have initial positive and final negative margin,
not the required negative-before-positive sequence. A solitary qualified edge
occurs240.848ms, then no continuation; NO_LOCK at360.006ms.

This supports investigating initial phase/rotor motion, not simply loosening
confirmation counts. It does NOT prove mechanical reverse rotation or that the
electrical feedback is free of switching/demagnetization contamination.

## Single control variable

Keep both alignment vectors and their30ms holds, second-vector request360,
acquisition request400, first waiting deadline30ms, one-shot rescue schedule,
360ms total acquisition deadline, ADC polarity/hysteresis/confirmation and
six-real-edge handoff exactly as in S4N-STATS. Keep both recorders.

At the second alignment's exit ONLY, choose the first acquisition vector one
normal sequence step farther ahead:

| Direction | Old physical sequence | Experimental sequence |
|---|---|---|
| Forward | align5,6 → drive1,2,3… | align5,6 → drive2,3,4… |
| Reverse | align3,2 → drive1,6,5… | align3,2 → drive6,5,4… |

Commanded vector distance from final alignment becomes120 electrical degrees
instead of60. This is NOT actual rotor angle or measured torque angle. The
experiment tests a different launch phase; it does not claim120 is universally
optimal. It can worsen kicks, torque or current. No automatic repeated vector
search or extension of drive time is introduced.

`FD_REV_LAUNCH` is emitted once on alignment exit. The adapter sets predecessor
step1 and calls the existing `commutate()` once. Physical step1 is skipped, not
briefly energized. Existing bridge/ADC phase publication, guard reset, deadtime
and safety gates still run. No synthetic crossing, retry or IIR sample is added.
Future accepted edges/timeouts follow the unchanged normal sequence.

Electrical transition detail: non-adjacent vectors can change PWM directly to
static LOW, especially reverse C phase. Before selecting the new predecessor,
the adapter calls allOff and holds all legs off for5us using DWT, under the
existing critical section. This is a one-time break-before-make interval, not
a post-ZC delay; timer complementary deadtime alone does not guard static GPIO
mode transitions. The gap exceeds configured2.3us timer deadtime, but board
gate turn-off behavior is not oscilloscope-validated. Absolute360ms budget is
unchanged; physical first-drive onset shifts by the short gap.

Opt-in `FD6288_LAUNCH_ADVANCE=1`; default0 preserves old behavior. Requires the
S4N statistics baseline; build script gives it a separate -launch object folder.
Trace variant36. Running timing/EEPROM/PWM24kHz/protections are unchanged.
Running recovery remains an offline prototype, NOT enabled in this HEX.

## Verification / next bench observation

Tests cover mirrored forward/reverse vector sequence, no early/repeated launch,
both dwell durations, ramp/hold, absolute deadline, timer wrap, startup reset and
six-real-edge handoff. Existing scheduler/sector-statistics tests must pass.
Build onlyCUSTOM_FD6288_G431; main-only HEX bounds must excludeBL/settings.

After authorized flashing, capture one normal trial, then a failed trial if it
occurs: return zero, stop, keep power, read before another start overwrites stats.
Use the same throttle; stop testing if kicks/heating become worse. Compare the
new first physical sector2/6 against the previous launch, allowing for different
floating phase. Do not call a small batch's success rate proof of reliability.
This is an unvalidated bench experiment, not a flight-ready build.
