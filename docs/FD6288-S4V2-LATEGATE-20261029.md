# S4V2：先检查时间，再计算重试资格（未烧录）

## 确认的问题及未确认的因果

S4V首轮6/12接管、第二轮3次救起、3次失败，较前轮体感明显变差，设置相同。
源码中fdRevCanReposition和fdRevDeadlinePolicy均先调用fdRevRetryEligible，再判断390ms时间门槛。
S4V加入missing_sectors/seen/confidence/末边沿时间等判断后，这些计算被内联到关中断的热路径。
不是只有390ms后才运行新代码。以前“控制决策一致”的主机测试未覆盖执行耗时，这一表述需要明确区分。

实物ELF反汇编确认：S4V fdBenchService的0x08001fd4开始读取missing_sectors并比较，
先于0x08001ff8的后续时间比较。函数大小S4U 0x334、S4V 0x390；fdRevTick分别0x80c、0x92c。
函数字节数不是耗时测量。确认存在不必要的执行路径，但尚未证明它造成首轮成功率下降；
没有实机完整ISR/关中断周期测量，电池温度和初始位置差异也未隔离。

## 修改

两处先判断时间，390ms前跳过资格计算。推进策略还先检查扇区是否到期。
将资格函数改为noinline，使复杂判断留在低频分支，避免内联膨胀高频代码。
S4V2反汇编fdBenchService：0x080020ca/0x080020d0两次时间比较，
未通过则绕过0x080020d8的fdRevRetryEligible调用；反汇编随产物保存。

保留已有有效补救：孤立边沿后3个完整空扇区且67.5ms无边沿可获得重试资格；新反馈撤销资格。
仅维护小计数器的工作仍保留，不能称首轮机器码与S4U完全相同。
不改变首次矢量、功率、JEOS、60度第二发车、390..410ms窗口、820ms截止或原生保护。
不是完整回滚S4U，也没有新增恢复策略。当前板仍为S4V，尚未烧录候选。
