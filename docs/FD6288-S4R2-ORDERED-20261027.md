# S4R2：修正补救优先级与预算（未烧录）

## S4R实测证据

hardware-backups/S4R-flash-2lNbzD/capture-failure.bin.json：7次汇总，4次闭环后操作者归零，3次NO_LOCK。
第7次事件完整：150.096ms撤驱动、170.138ms重新定位、260.219ms重新发车、360.074ms唯一边沿、390.005ms截止。
最后一次确实补救失败，不是未执行；不能从一个孤立边沿推出只需延长时间就能起转。
用户描述“咔——咔咔”与释放/重新定位时序相符，机械方向与角度仍无直接测量。

## 设计疏漏

S4R曾声称不干扰旧启动路径，但“定位后60ms无边沿”会在试验150ms时截断原救援。
原路径：90ms定位结束；30ms首等待；22.5ms第二等待；142.5ms开始16/14/12/10/9/8ms六段救援，
211.5ms才完成。实测第7次142.657ms进入16ms段，却150.096ms就被撤驱动。
因此它可能破坏原本能恢复的启动。7次样本不足以定量证明成功率下降全由此造成。

## 修正

- 不再按60ms计时器直接抢占。必须旧救援已使用、剩余段数为0、当前扇区到期，且从未有过合格边沿。
- 必须有完整剩余预算：20ms释放＋30/60ms定位＋至少130ms启动余量，共240ms。
  130ms沿用S4R原先意图预留的余量，是调度下限，不是证明足够的电机参数。
- 本轮总390ms不变，已完成旧救援时至少已用211.5ms；即使立刻重试也至少需要451.5ms。
  实现进一步要求下一个正常扇区到期（理想234ms），预算更不足。因此当前参数下重新定位分支不会触发。
- 时限开始时间存入策略并跨重定位保持，不用剩余时间无符号下溢来允许超期重试。
- 旧反馈启动、救援、原生超时与保护都继续执行；无边沿则仍按原390ms截止。
- 故这是撤销干扰、修正组合逻辑，不是声称已经解决初始位置问题，也不是偷偷延长强拉。

释放/PWM/归零/故障适配器测试通过：因本预算下正常流程不会进入释放分支，使用明确标注的合成状态覆盖该分支。
