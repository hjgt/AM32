# Copilot三项建议与当前实现/历史对照（2026-11-07）

本次只核对代码、归档并离线回放，不修改固件、不烧录。当前板上HIZ-OBSERVE不发车；以下“启动当前实现”指ALIGN-PAIR/LAUNCH-TWO所沿用的ADC资格路径。

1. 首发消隐加长：合理的候选。comparator.c ADC_ZCD_BLANK_SAMPLES=1，按有效驱动ADC组计数，不是保证经过一个完整PWM周期；24kHz组间名义41.7us，实际首组可在换桥后约7us。归档/构建参数及相关Git历史未找到首发专用1→2/3组的严格单变量实测。先前0→500us是接受后的换向等待，不能当作做过消隐。ST六步调参4.2.3把退磁消隐与过零后换向延时分开，给出其方案通常不低于2–3 PWM周期的建议；不能把该数直接当成本板最佳值，消费组数也不等于精确经过周期数。

2. 15%..80%时间窗口：需先定义周期。首次反馈没有相邻真实过零周期，30ms是等待上限而非电周期；若拿30ms做分母，15%=4.5ms，连已读正常4.032ms首事件也会挡住。S1/S2曾使用命令扇区12.5%..87.5%窗口，S4Q有命令扇区1/16..15/16窗口；它们是有计划步进周期的另一种启动结构，不是本次首次反馈的已知转速。当前获取期earliest明确为0；闭环已有基于真实周期的早事件门限。不能照搬百分比作为首次检测判据。

3. 连续3–5点与方向：方向早已执行。正向step2观察浮空A下降，step3观察浮空B上升；每扇区必须先采到预期前侧，再跨过±8滞环并连续确认后侧。启动目前2个新鲜有效ADC组，滞环/反侧/无效会打断确认；非单点。高速路径可降至1组，但不是本次首发条件。归档未找到保留前侧及方向，仅把首发后侧2点改为3–5点的单变量实测。STARTUP-LEVEL/EVENT试过7点，但同时改变前侧资格/事件语义，不能等同这项实验；其不良结果也不否定保留原资格后增加点数。若“3–5次”指完整独立过零事件而非ADC样本，不能在固定首发矢量内等它们再换向；正常闭环接管已有六个连续事件要求。

## 离线回放：LAUNCH-TWO未转trial86

完整密集首扇区原ABC仍保留，可在实际第一次换向前重算资格，结果存FD6288-ZC-FILTER-REPLAY-20261107.json。原桥状态/真实轨迹保持原样，只预测检测器接受时间，不预测改变换向后的反事实运动。

- 原1组blank、2点确认：约0.497ms接受。
- blank改2/3组、确认仍2：均约0.497ms，仍通过。
- 保留1组blank，后侧3/4/5点：约0.533/0.575/0.616ms，仍通过。
- blank4组会丢掉本扇区原先全部前侧，在原约1ms首扇区窗口内不再接受；这不是证明噪声已被清除，也不代表继续保持首矢量以后永无新穿越。

因此这条失败不符合单点尖峰解释。简单两倍消隐或五点后侧确认都不会在原ADC轨迹上排除该候选，增加确认也会增加检测延迟。不能凭ST通用值或确认点数宣布修复。

较有信息增量的后续依然是保留单首发激励，取得早事件样本在不反馈换向时的完整后续ABC，用独立影子判据/离线回放比较不同消隐与确认，看是否有后续新的同方向穿越。解除屏蔽时须重新建立前侧→后侧，不能把持续后侧在时间到达后补成新过零。完整首发已测试机械约50次，但只有约7.8ms首事件样本留有全曲线；缺少约0.5ms早事件在不换向时的完整曲线，不重复要求50次机械观察。
