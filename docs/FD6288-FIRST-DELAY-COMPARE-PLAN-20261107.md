# 首次换向延时2ms建议：历史复核后撤回直接实施（未实现）

用户询问下一步如何测。本页为建议，尚未修改/编译/烧录，板上仍HIZ-OBSERVE。

## 历史复核修正

用户提醒以前做过延时实验，复查代码、Git、归档及旧对话“审计ADC过零与换向链路”的全部可读轮次。确认：

- 10月19日S4G-SEED：首次合格反馈后从立即换向改为等待500us；随后NOEDGE记录实际等待约565us（含当时服务量化），下一扇区仍无法建立反馈。不是500us→2ms。
- 10月30日FIRST500：在ADC一致性/TIM16修复后再次做首事件0→500us单变量。8次中6次接管、2次失败；末次接受后518.3375us发布新扇区，第二连续边沿仍未建立。结论是无改善证据，不支持继续加大固定延时。
- 旧S4F/S4G还存在第2..5边沿按真实间隔计算、最大3ms的等待；这是另一项，不是首反馈固定延时已延长到3ms。
- 此次核对未找到首事件500us→2000us已烧录/实测的记录。下面2ms是本次刚提出的新建议，不得写成已试参数。

因此撤回“直接实施2ms作为优先下一步”的建议：需要先衔接上述无收益历史并说明300ms定位、隔离两矢量条件下的新实验到底补什么证据，不能只因为看到一个早事件就继续猜固定等待。没有修改固件或烧录；板上保持HIZ-OBSERVE。下面保留原建议用于审计，不作为待执行指令。

## 依据

单首发固定30ms，用户约50次随机初态均正转半圈；LAUNCH-TWO允许第一次反馈换向后，出现少数咔后未转。已读取未转trial86首事件约0.503ms、事件后约0.518ms切走首矢量；正常对照首事件4.032ms，同样约0.518ms后换向。失败第二矢量30ms全前侧，正常16.439ms获得第二接受。关联指向首次切换作用，但另有历史约1ms首事件仍能正常启动，不建立通用最短事件阈值。

HIZ-OBSERVE两条完整窗口都在关桥后快速回到ADC零端附近，后续最大线间跨度7计数；降低明显残余运动的排查优先级，仍不证明零速。本实验不再调整定位。

## 建议B档

以归档LAUNCH-TWO作为A档（首事件后500us），B档只把第一次反馈换向延时改为2000us。定位仍30+300ms，功率、首发/第二矢量、原过零资格保留；无首事件仍30ms截止。原TIM16排期，只换向一次，第二矢量固定30ms后关断，无第三矢量/重试/闭环。2000us是诊断对照量，不是最终参数。

记录仍从首发到第二矢量结束，保留两组末段快照、实际首事件、实际桥切换和完整第二响应；不能只是静默改宏，须同步覆盖新最长时长的记录范围和总时限（候选63ms记录/394ms整轮软件上限），并标明新模式/版本，避免将其当原61ms/392ms ABI6。输出日志和原始样本不得驱动控制分支。

## 用户操作和判断

先5..10次随机初态，观察是否从咔后不动变为正转；失败立即归零保电读取。若本批顺利，读末次与轻日志，检查首事件时间是否覆盖原约0.5ms的早事件类别。只有较晚事件的一小批顺利，不足以说明同类失败被改善；不要求盲目追加几十次。

最有价值的成对证据：仍出现很早首事件，延后换向后第二矢量获得预期穿越且有正向动作。这支持原切走首矢量过早/接续相位有影响，不独立证明早事件虚假或功率不足。若同类早事件仍导致全前侧无转，重点回查首发矢量、检测相位/方向及其激励响应，而不是继续靠延长第二等待。若失败为首事件全缺失，它是另一类，不可拿本次仅改反馈后延时作同类解释。

实际实施前的必要检查：新延时确由同一TIM16路径执行，窗口/总上限覆盖最晚首事件，保护/归零不被延时覆盖，首事件后只排一次，关闭开关字节回归对应基线，现有缓冲有界。不因本计划自动执行烧录。
