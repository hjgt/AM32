# S4R：反馈启动＋一次无边沿重新定位（未烧录、未实机验证）

## 为什么不继续S4Q

读取hardware-backups/S4Q-flash-m6s3Y7/capture-failure.bin.json：9次均NO_LOCK，
8次有ADC合格边沿，第6次完全没有；最大连续策略资格1～4。最后一次5个边沿、最大资格1，
连续四个扇区的边沿相位约99%、93%、64%、24%，固定计划/筛选未能接管。
详细记录只覆盖前24扇区，末11扇区未保留，不能推断其详细运动。
用户看到所有启动均卡顿、转半圈后停。S4Q失败，不能继续声称固定节奏改善启动。

S4R关闭FD6288_PLANNED_ACQ，恢复S4P的反馈路径（前5个边沿立即换向，第6个测量延迟接管）。
既有定位30+60ms、原启动功率、正常闭环、进角、JEOS/异步换向均保留。
不是恢复纯旧HEX，而是在原反馈路径上增加一个狭窄、独立开关的补救分支。

## 条件与动作

1. 原定位结束后60ms内一个策略接受的ADC合格边沿都没有，且仍在启动OPEN阶段，才允许补救。
   任何一次合格边沿永久关闭本次冷启动的补救资格；不针对“已有边沿后失败”或运行失步重试。
   60ms是约两个旧等待周期（30+22.5ms）之后的实验分界，不是已证明的转子停转时间。
2. 转入RELAX，全桥高阻，取消异步换向，PWM与旧占空比爬升状态清零。
   20ms释放从实际关桥之后开始计时；不忙等，不以电气时间保证机械停稳。
3. 在相同总试验内，仅重置启动策略，换一组定位：
   首次正向5→6→2，重试1→2→4；首次反向3→2→6，重试5→4→2。
   这是把定位矢量整体平移两个扇区，不改变请求方向；不能保证新定位必然成功。
   定位第一段重新210→360软升，第二段保持360；重试发车保留原5us全关过渡。
4. 然后继续原反馈启动，不跑S4Q固定16→8ms节奏。

## 边界与保护

- 只允许一次重新定位；不清零试验开始时间，不延长390ms绝对截止。
  典型150ms关桥、170ms重定位、260ms发车，约余130ms接管，可能不足；不隐藏这一折衷。
- 原生堵转/安全限制锁存、原生超时计数不清零；已使用的旧救援预算不重新发放。
  故开启堵转保护可能先于重新定位停机，不通过清除保护来强制重试。
- RELAX期间PWM最终写入口强制0，JEOS只清标志、不做过零判决；归零/故障/总截止优先于重试。
- 未修改BL、EEPROM、启动入口或运行失步恢复。此前离线运行重捕获策略仍未接入MCU。
- 不宣称可飞行，也不宣称堵转保护已验证；这仍是带硬时间边界的台架实验。
