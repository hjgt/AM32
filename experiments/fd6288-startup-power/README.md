状态更新（2026-09-21）：**P0/P1 已集成为仅供台架的候选，已编译和离线
验证，未刷板、未通过实机验收。** P1 短时加力 +40；P0 不加力但使用相同
300 ms 关断窗口。交付与步骤见
[测试固件说明](../../test-firmware/fd6288-startup-power-20260921/README.md)。
以下保留 9 月 20 日设计依据；不能把软件测试当作电机或硬件保护验证。

## 为什么先验证用户提出的启动加力

现有记录证实的是“未建立过零闭环”，不是“启动功率肯定足够”。
失败后的 2.5 A，不能反推起转最初几十毫秒的有效转矩足够：

| 保留事件时刻 | 正常 capture 1 | 异常 capture 2 |
| --- | --- | --- |
| 约 20 ms | duty 360，过滤电流 0.37 A | duty 360，过滤电流 0.31 A |
| 约 42.5 ms | duty 360，过滤电流 0.68 A | duty 360，过滤电流 0.61 A |
| 首个非超时 ZC 函数事件 | 约 53.4 ms | 整个试验无合格 DRIVE 过零 |
| 第五个连续非超时 ZC 函数事件 | 约 97.5 ms | 无 |

这些电流已经过滤，不能当作瞬时相电流或用差值证明初始扭矩不足。
但短时增加驱动力是合理的待验假设。ST 的启动调试资料也指出，起转电压/
电流不足可能出现抖动及吸收电流增加，适当提高可能改善；过高同样会引起
过流。它支持试验方向，不给出本电机适用的幅度或时长。
参考：[ST UM3259 §3.1.1–3.1.2](https://www.st.com/resource/en/user_manual/um3259-stm32-motor-control-sdk--6step-firmware-sensorless-parameter-optimization-stmicroelectronics.pdf)。

### 地面站的 150% 实际如何作用

当前 `loadEEpromSettings()` 接受 startup_power 的范围为 50..150。
当前最低 duty 参数=1、固定 C03 补偿=200，故：

```text
minimum_duty_cycle   = 1*10 + 200       = 210
min_startup_duty     = 1*10 + 150 + 200 = 360
startup_max_duty     = 1*10 + 400 + 200 = 610
```

内部 duty 满量程为 2000。360 相当于名义 PWM 占空比约 18%，不是
150% 电压/电流/机械功率。610 是现有启动阶段上限，不是建议加力到的值。
**不能直接把 EEPROM 的 startup_power 写成 200**：当前范围校验会走
非法值分支，把启动下限退回到 210，反而更弱。原型不改这个字段或其语义。

## 第一阶段：只改变短时启动下限

基于 A 的控制决策设计 P0/P1，不先合入 B 的周期修正，也不同时加入新的
相序、预定位、开环加速、进角或 ZCD 阈值，便于解释对照结果。

| 项目 | P0（对照） | P1（首档加力） |
| --- | --- | --- |
| 启动下限额外偏置 | 0 | +40 / 2000 |
| 当前配置下的下限 | 360，约 18% | 400，约 20% |
| 加力保持 | 无 | 最多 100 ms |
| 加力退出 | 无 | 20 ms 线性减去额外偏置，最晚 120 ms 归零 |
| 提前退出 | 无 | 连续 5 个合格 DRIVE 边沿后开始减去偏置 |
| 相序、ZCD 校验、超时推进 | 现有 A | 与 P0 相同 |
| 台架测试窗口 | 300 ms 后请求关桥锁止 | 同 P0，包括正常起转也结束 |

100/20/300 ms 和 +40 是**待上板验证的试验设计值**，不是额定安全值。
时间选择参考现有正常样本约 53 ms 获得首边沿、约 98 ms 获得五个边沿，
不能代表所有转子角度/电池状态。还保留 +80（约 22%）作为另一次人工
决定的后续试验选项；P1 不会因失败自动升级至 +80。

规则：

1. 只有已观察到明确的操作者零油门、且原生逻辑允许的冷起转才允许加力。
   不用于 Coast 旋转接管；不绕过 armed、故障锁止或重启禁止条件。
2. 每个正油门期间最多一次。超时、失同步、内部 input=0 均不能重新给
   加力脉冲。只有操作者明确回零，下一次合法冷起转才重新获得资格。
3. “连续 5 次”来自 ADC 私有的真实 DRIVE 接受计数，不能用 A 的
   `zero_crosses`：后者混入超时强制推进。5 次只用于退出加力，**不改
   现有换相模式/闭环接管资格，也不等于已经证明机械同步**。
4. 偏置只作用在现有 startup-floor 分支。返回的是下限请求，仍经过
   原斜坡、启动上限、运行时有效保护上限和最终 C06 检查。不能用提高
   `last_duty_cycle`、最小 ADC 脉宽或直接写 PWM 绕过这些上限。
5. 原有启动条件结束或 Coast/故障发生时，不再应用额外下限。功率退出
   后保持原控制，不修改正常运行、低油门、刹车或传感器标定。

### 这是一个控制变量，但不只影响转矩

按当前 ARR=6665、160 MHz、现有 PWM/CCR4 计算式，预计：

| 下限 duty | CCR1 请求 | CCR4 触发位置 | 名义 ON 脉宽 |
| --- | --- | --- | --- |
| 360 | 1200 | 600 | 7.50 µs |
| 400 | 1334 | 667 | 8.34 µs |
| 440 | 1467 | 733 | 9.17 µs |

数字描述定时器请求，不是实测门极导通时长。提高下限既可能改善转矩，
也会让原来的 ON-window 采样更晚、脉宽更长。所以即使 P1 改善，也不能
单凭成功率就断言纯粹是功率不足。下一次必须保留原始三相值、判定原因、
CCR1/CCR4、首次/连续有效边沿的时间及过滤电流。

已复核主文档 C02 的实测回退记录：不恢复那次统一 460-tick 采样 floor，
不改死区 0xCE 或固定补偿 200，不把数字 valid 当成物理采样正确的证明。

## 台架关断护栏及堵转保护

为了不重复之前持续约 2 秒的失败，设计上 P0/P1 **共同**带 300 ms
台架窗口：从合法冷起转开始计时，窗口结束后必须六管关闭并锁止，正油门
不允许自动重试，明确回零才解除。这会让正常起转也主动结束，因此将来
这两个候选只用于固定台架、不能飞行，不能当作正式版发布。

它不是地面站启动判定超时：零油门、上电等待、BL/主程序握手期间根本不
启动该窗口。不写 BL/F800，不修改网页、串口或 DShot 设置。

9 月 20 日的纯策略原型只产生 `stop_reason`。9 月 21 日已另接入关桥
适配层、锁止和末端输出检查，并用实际函数做离线寄存器测试；尚未实测
关断延迟或硬件输出。提高下限后的热/电流风险不能靠软件窗口证明安全。
原先 A 固件没有这个窗口，本轮也没有刷板，不能认为板上已经更新。

集成时的必需项：

- 独立服务测试窗口，即使已经超过原 startup-floor 的 30-cross 分界，
  仍须在窗口结束时请求停机，不能把服务只放在启动下限 if 分支里。
- 专用台架停机原因/计数，与原 stuck-rotor trip 分开；先发布锁止，
  取消待执行换相，关桥，清 PWM，最后写 PWM 的分支也检查锁止。
  单独令 floor=0 不够，原油门映射和 ADC 最低脉宽可能再次产生输出。
- 原生 `Stuck rotor protection` 的开关、阈值、计数与回零解锁规则
  不变，不为功率脉冲清空或延长其保护。台架窗口是额外的实验限制，
  不冒充原生堵转保护的验证；功率改变仍可能间接影响超时数量/触发时刻。
- 原型采用单一所有者的状态。主循环/ISR 的真实共享访问必须另加审查
  与测试，不能原样拷贝后假定没有竞争。
- 计时必须使用不被换相清零的时基。若用 160 MHz DWT，先做无符号
  cycle 差再比较；不能对绝对 CYCCNT 先除以 160，也不能用反复清零的
  INTERVAL_TIMER 当作绝对起转时间。硬件运行时必须验证时基已开启。
- 记录并测量服务延迟、阻塞 ISR 和最终关断延迟。这是软件窗口，不是
  硬件逐周期限流或绝对 300.000 ms 的断电承诺。

上述适配层已做离线验证后生成测试 HEX；实际窗口关断、实时性和门极输出
仍须先卸载验收，仍需独立安全中止手段。台架版禁用 Coast 旋转接管，
每次都必须等转子完全停止；普通版本不受此限制改变。

## 验收与后续决策

先完成适配层/故障关桥/待执行换相等测试，只构建 `CUSTOM_FD6288_G431`，
再由用户确认停稳后刷主区并验证 BL/设置不变。先卸载验证启动、窗口结束
确实停机、保持正油门不重启、回零解锁、地面站与遥测，然后才做有防护的
短时带载 P0/P1。记录电池电压、负载、温热状态；异常随时手动回零，不为
等待自动停止继续维持异常。P0/P1 的正常停止提示不能被误当成新失步。

每次只触发一次并停稳保存。先做小组对照判断是否值得扩展，不拿少量
全成功证明 20% 故障消失。重点比较首个/第五个真实边沿时间、强制超时
次数、失败是否仍为 0 合格边沿、功率退出附近是否重新失步、电流趋势。

- P1 改善且无新异常：再验证更广泛起始状态和解除台架窗口后的持续运行，
  然后单独评估 B 时序改进与堵转保护 On；不能把台架版直接改名稳定版。
- 仅电流增加而过零仍为 0：停止增加功率，转向预定位/递进开环/接管设计。
- 只在退出加力时失步：分析功率交接、周期估计和负载，不先延长大电流时间。

第二阶段预定位/开环不是本轮已实现内容。需要将有计划的开环步进与
真实过零、异常超时区分，单独决定保护预算与接管规则；不照搬其他电机
的对齐时长/加速度，不通过虚构 ZC 或清除保护计数使其“看起来成功”。
算法分段可参考 [ST UM3468 §2](https://www.st.com/resource/en/user_manual/um3468-stm32-motor-control-sdk-6step-startup-configuration-stmicroelectronics.pdf)。

  持续正油门、回零解锁、真实过零提前退出、DWT 回绕、阻塞 ZC 等待、
