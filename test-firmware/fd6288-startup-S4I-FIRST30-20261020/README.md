基于S4H-SPLIT，用户授权后只改变第一驱动扇区的无反馈等待：
22.5ms → 30ms。不是恢复S1固定定位/强制加速。
有合格过零时仍按现有500us种子延迟推进，不必等满30ms。
首次超时或首次反馈推进后，普通等待恢复22.5ms；以后即使回到
物理step1或连续反馈断开，也不重新获得30ms等待。

两次连续无反馈后仍只有一次16/14/12/10/9/8ms补救，六边沿接管、
ADC资格、后续相位延迟、300ms整体截止及原生保护代码不变。
全无反馈时补救约从62.5ms开始，而非45ms；超时计数的实际时序
随之改变，不能声称保护时间响应完全不变。多7.5ms同矢量施力
会增加通电时间/改变运动过程，不是已验证的定位完成判据。

## 复查依据

历史S1提交84e42f3为固定30ms step1、随后12→4ms强制加速，
累计六个相位/周期合格边沿前不会让单个边沿直接引导换相。
首次实测22.69ms的ADC接受位于ALIGN，策略忽略；后续8次也都未接管。
这些结果不能孤立地证明定位有效或无效，不能直接恢复整套S1。
本次保持现有事件优先策略，仅测试首次无反馈等待。

最初考虑40ms，但源码核查TIM2为0.5us计数、ARR65535，32.768ms回绕。
为不额外改变计时器/采样语义，发布候选改为30ms；40ms构建仅为本地
中间产物，未发布/未刷入。30ms加现有500us延迟仍低于正常计时回绕点；
异常调度迟到不据此得到保证，DWT总截止与禁止追赶突发规则保持。
