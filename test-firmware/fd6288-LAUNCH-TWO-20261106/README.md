## 观察目标与已有证据边界

已有正常启动记录已经证明：首次反馈换相后，顺滑样本第二扇区约13.77ms/21.02ms接受；失败样本约22.5ms未接受后被切走。该阶段已定位，无需重复证明。见 [证据审计](../../docs/FD6288-FIRST-COMM-EVIDENCE-AUDIT-20261106.md)。

本版唯一主要新增的控制实验是：保持第一次反馈换相后的矢量到30ms，补足原22.5ms超时以后约7.5ms的响应。同时保留该次首次事件及换相前后的数据，供比较不同首发响应。它不预设“延长就能解决”，也不引入最短事件拒绝门槛。

用户最新观察：300ms改善起转平顺性，已经能起转的往往不再磕绊；但仍有完全起不来的试次，感觉成功率与ALIGN-PAIR接近。文档分别记录平顺性改善和持续存在的不起转问题，不将其合并为“300ms完全无效”或“已解决”。原始日志中个别超时后接管记录仍原样保留。

## 实现流程

1. 沿用原30ms第一定位、300ms第二定位，原首发矢量及换相前5us关断。
2. 第一发车矢量等待原ADC资格的首个合格事件，最多等30ms。若没有事件，到期关断，不强制推进。
3. 有首事件时，沿用TIM16绝对截止调度等待500us，然后只执行一次反馈换相。正转为step2→step3；反转为step6→step5。
4. 第二发车矢量从桥配置完成返回后保持约30ms。第二个合格事件只记录，不安排第三次换相；没有事件也保持到上限。第二扇区不再执行原22.5ms超时推进。
5. 到期关断，禁止第三个发车矢量、重定位、重试和闭环接管。保护/归零路径保留，正命令不能自动重触发，归零后可重新触发。

第一事件可在首发后0..30ms内到来，再加500us及第二段30ms，正常两段发车激励最长约60.5ms；整轮另设392ms软件截止，不随事件续期。服务或定时器迟到仍按既有停止规则处理，不保证独立硬件定时关断。正常结束仍用原因13 launch_hold_done；没有连续起转是本诊断预期。

配置在单首发版之上仅增加FD6288_LAUNCH_TWO=1，要求原FIRST_EDGE_500US启用。ADC触发、三相读取、前侧资格、判决算法、原占空比请求及功率上限不变；只允许最多两次接受，confidence最多2，不构造六次接管证据。

## 记录如何覆盖新增窗口

复用同一12404B缓冲，ABI6保留末段两快照及最多512条发车数据；不增加ADC转换、串口或等待。

- 首发记录上限从40ms扩到61ms，以覆盖常规时序下第一段最多30ms+500us+第二段30ms。仍在提前停止时冻结。
- 每个发车矢量的前约2ms保留每个实际消费组，其余每4组留1组，ACCEPT无论抽取相位均保留。典型24kHz消费时分别约41.7us/166.7us间隔；记录缺组和程序时间以实际文件为准。
- 抽取后的记录计数和跳过组数分别保留；遇512条或61ms先到会冻结，检查文件实际覆盖范围，不能把缺少的后段视为稳定。
- 首发和第二扇区都有独立step/sector标记。第二扇区初始2ms密集窗口以首扇区close的程序时间为参考，不是硬件采样时刻。
- PB7保持现有语义：首发配置完成拉高，第一次反馈换相拉低；若没有首事件，则到关断才拉低。不增加新的物理同步信号。
