## 实验目的

此前ALIGN-TAIL成败对照：两次首有效margin相近（成功−48、失败−41），但首事件分别在发车后7.936ms/0.911ms；成功下一扇区接上，失败下一扇区超时。两点定位快照未提供足以分成败的阈值。需要把首发自身的电压响应与首次反馈换相的作用分开。见 [成败对照](../../hardware-backups/ALIGN-TAIL-flash-20261106/RESULT-smooth-comparison.md)。

## 行为

- 在ALIGN-TAIL基础上开启FD6288_LAUNCH_HOLD=1，保留第一定位30ms、第二定位300ms，然后沿用原首发矢量与换相前5us关断。
- 首发桥配置完成并返回commutate后，以当时DWT重新锚定30ms保持。保持期间不再换相、不重试、不进入闭环；输入/保护仍可提前停止。
- 正常流程名义总计约360ms，另从trial起设361ms软件截止，给现有服务少量余量；事件不会续期。它不是独立硬件截止，实际关断需结合服务延迟解释。
- 保留ADC采样触发、前侧资格及判决算法；合格事件仍记录，但策略只保存第一次观察时间，保持OPEN，不转PENDING，不启动换相定时器，confidence保持0。FIRST500参数虽保留，本诊断不执行其后续换相。
- 第一次接受后既有ADC状态会标为reported，但三相及margin仍按原路径读取/记录；不要把reported当作重新确认的机械过零。
- 到期用原停止通路置inhibit、冻结记录、关桥、清PWM并取消计划换相，正油门不能自动重触发；操作者归零后才可重新触发。
- 正常结束原因13：launch_hold_done，不记作no_lock。无闭环/最大连续0是诊断设计，不能按正常启动失败解释。

## 观察和记录

现在是定位后施加一次首发矢量并关断，不会连续起转。肉眼描述定位后那一下如何运动、是否回摆即可，不要求与PB7精确对时。

保留ABI5定位末两快照和原首发记录器。PB7在原首发桥配置完成后拉高，到关断拉低，高段约30ms。首发记录器仍有40ms/512条上限，但本版通常在约30ms停止时提前冻结，保存首发固定矢量全窗口的前2ms全组及其后隔组数据。未追加ADC转换或串口输出。

测试一次后归零保持通电，使用本目录ELF只读采集；新trial会覆盖前一份，未读前不要再启动。继续按同版、相似观察条件记录不同初始位置，不要求大量重复。本次目标是看首发电压轨迹及动作，不以连续起转判断成败。
