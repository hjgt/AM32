# S3：恢复过零驱动的启动换相（台架候选，未刷入）

2026-09-22：已编译和完成软件回归，**未刷入、未实测、不可飞行**。
本轮没有连接、暂停、复位或写入电调。板上最后已知仍是 S2D2。

## 为什么改这一处

S2D2 重连后 8 次仅第 5 次完整闭环观察，首次失败在定位期 14.16 ms
已接受一个边沿，却因固定定位规则未推进，之后开环全程无接受边沿。
成功样本到约 292 ms 才形成连续六边沿。
这些记录支持优先审查强制节奏与反馈不匹配，但不能证明唯一根因。

对照 `2c1b5fa` 的 `zcfoundroutine()`：原轮询启动的前五次过零不等待
相位延迟，直接推进换相，第六次开始等待。S1/S2 改成固定定位/开环
加速、六边沿前不响应反馈换相，是明显不同的控制策略。
S3 恢复这一早期响应方式，不完整回退旧固件，也不恢复损坏设置。

## 控制规则与差异

- 保留 S2 的首次物理矢量 step 1 和既有转向映射；取消固定 30 ms
  定位停留、12→4 ms 加速表及迟到保持表。
- ADC 的有效窗口、前侧→后侧、迟滞、鲜样本确认、相位极性不变。
  前五个接受边沿在同一次处理里立即推进下一相，不再等预定节拍。
- 第一个边沿不估算转速，第二个连续边沿给出真实间隔，后续做原式
  平滑；第六个边沿按真实间隔和提前角等待后接入原闭环路径。
- 六边沿在 S3 指无反馈超时隔断的连续 ADC 合格边沿，**不是 S2
  固定扇区 12.5–87.5% / 周期间隔 75–125% 的资格条件**。
  不再有预设换相周期，因此不沿用对应的固定节拍窗口。
  六次计数只决定计时方式切换，不能独自证明转子稳定同步。
- 单步 22.5 ms 无接受反馈才试探推进；重置连续计数，不伪造过零，
  不用试探间隔污染转速估计。一次延迟服务最多推进一步，不补发突发。
  首次等待也用完整 22.5 ms，而不是旧启动计数种子造成的约 20 ms。
- 功率请求保留首 30 ms 为 360、后续启动为 400（0..2000 标度），
  无提高上限；30 ms 只是功率包络，不限制边沿换相。
  接管后的 +40 退出规则和所有最终保护上限保留。
- 启动获取仍最多 300 ms；只有第六边沿延迟完成才获得最多 1 秒观察，
  第一个闭环缺失反馈超时立即停止。失败/观察结束后须实际回零才可再试。

## 堵转保护与不改范围

原生堵转开关、主循环阈值选择、故障锁存未改。S3 的实际无反馈试探
重新进入原生超时计数和锁存检查；真正收到边沿的推进不算超时。
当前设置仍 Off，本轮没有写 EEPROM。测试程序注入超时，验证 Off/On、
计数超过阈值后的驱动封锁与回零恢复，但这不是带载误触发验收。
300 ms 台架截止可能先于原生保护，特别是低输入阈值为 100 时；
不能把自动停止当作原生堵转保护已经有效。

BL、F800、地面站入口、前向编程、PWM 频率、死区、过零极性均未改。
没有添加地面站入口超时兜底。

## 最小实测与读取

得到刷写授权后只刷主 HEX、一次校验；不重新全读旧固件、不刷新设置。
首组最多 5 次，沿用上一轮设置/负载和接近的电池状态，先保持堵转 Off。
人工给油门，出现卡顿/异常电流立即回零，不为凑 1 秒强行维持。
每次回零且完全停稳再起转；若明显恶化提前结束。保持供电后只读：

```sh
node tools/scripts/fd6288_pair_capture.cjs dump obj-startup-S3-feedback/AM32_CUSTOM_FD6288_G431_2.20.elf NEW-S3-PAIR.bin --stopped
```

记录接受边沿→实际推进、连续计数、超时重置、接管时间、完整 1 秒观察、
电流/电压与日志耗时。两块记录保留第一完成失败和第一完整观察成功。
S3 的 `retry_deadline_us` 表示无反馈试探截止，不是实测或预定扇区长度；
`sector_percent=255` 表示不适用。最多 72 个启动扇区，反复部分连贯后
再超时可能超限；溢出显式标记、不覆盖前段，溢出后不得声称全程证据。
