## 详细记录的证据与边界

#1 在约 20.0、42.5 ms 强制超时推进；这两处实际 PWM CCR1=1334、
duty=400，说明加力确实进入输出链路。约 44.22 ms 开始获得非超时 ZC，
第五次约 86.04 ms；91.86 ms duty=390、97.16 ms duty=378，可见提前
淡出。约 300.003 ms 记录台架结束，最后一次接受过零约 299.522 ms。

仍可看到 A 路径把强制超时当作 ZC 来更新 IIR：10000 → 18753 → 25327
个 0.5 µs tick。该问题是已知且可修复的，但成功记录也存在它，不能说
它单独解释了七次完全无过零。P1 没有合入 B 的周期修正。

详细 trace 保留 ADC 样本 #1–64 与 #3965–4476，中间 #65–3964 缺失；
事件保留 #1–32 与 #56–183，中间 #33–55 缺失。七次失败只有独立摘要，
本次没有它们的原始三相波形。不能推断它们一定反转或精确卡在哪个扇区。

过滤电流范围成功/失败有重叠，失败最低电压约 8.0 V；不支持仅凭这些
读数归咎于明显电池掉压，但不能排除瞬时尖峰/跌落。300 ms 的过滤电流
也不能直接与以前持续 2 s 后的 2.5 A 比较，宣称效率改善。

保护开关仍 Off，stuck trip_count=0，不能证明堵转保护已可用。
数据足以结束本轮“小幅加力即可解决”的试探，转向启动引导和过零接管；
不足以宣布根因已唯一锁定或放行飞行。不要继续重复刷测同一 P1。

## 后续效率约定

常规同板主固件迭代：零油门/停转检查 → 只写主 HEX → 一次写入校验 →
少量运行态检查。已有完整备份留作回滚，不每轮完整读旧 Flash/新 Flash。
只有固件身份不明、链接异常、地址布局或 BL/设置改动时，才扩大检查。
采集在已验证会话用 `dump ... --stopped --quick-dump`；它只允许读取，
不能用于跳过 RAM 重准备命令的完整身份检查，不冒充完整 Flash 校验。

用户目标为今天至最迟明天获得可飞且堵转保护可用版本。后续集中为一次
候选、分阶段测试：先可靠带载起转，再保护 On 不误停与卸载故障注入，
最后正常工作转速/电流温升/回零验收。不得因时间目标省略这三个放行条件。
