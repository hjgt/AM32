## 两次失败共有的具体链路

两次失败事件环均无覆盖，ADC 尾段都覆盖了接管后的整个首扇区。

| 项目 | #8 | #17 |
| --- | ---: | ---: |
| 最后两个获取边沿的间隔（约 ms） | 6.732 | 6.631 |
| 传入接管的平滑周期（ms） | 12.2925 | 10.6155 |
| 初始化后的半周期门限（ms，0.5µs 分辨率截断） | 6.146 | 5.3075 |
| 首个保留的正侧候选距上次 ZC（计时器 ms） | 5.961 | 5.298 |
| 该采样判定 | early | early |
| 第一个保留的 unarmed 采样（计时器 ms） | 6.164 | 5.400 |

接管后先出现负侧 pre，经过迟滞区后出现正侧，但因早于时间门限
被拒绝。拒绝同时清掉了“已见过负侧”的状态。门限过去后，信号
仍在正侧，遂持续被判为 unarmed；随后回负侧但没有再次完成正向
跨越，最终在距最后有效边沿约 22.5 ms 处超时停止。

#8：233.950–235.684 ms 为 pre；236.296/236.398 ms 为 early，
236.499–244.864 ms 为 unarmed。#17：99.102–100.836 ms 为 pre；
101.244 ms 为 early，101.346–110.016 ms 为 unarmed。
这是降采样后保留的时刻，不能说覆盖了每个 ADC 调用。

代码对应：`fdRevTick()` 把 `fd_rev.measured` 的平滑周期传给
`adcZcdSeedHandoff()`，后者把它写入 `adc_zcd_last_real_interval`。
因此 `changeCompInput()` 取 `min(平滑周期, 最近真实周期)/2` 时，
两项实际上都是较长的平滑值，没有使用最近那段约 6.6–6.7 ms 的
真实相邻边沿间隔。快速加速时前面 16–22 ms 的旧间隔仍拖慢 IIR，
这与此处门限过晚的记录吻合。

**确认的是门限初始化使用了错误语义的周期，以及候选电压跨越被
拒绝的完整软件链路；候选跨越是否全部为物理真实反电势，仍需验证。**
下一候选应优先在接管时分别保留“平滑周期”和“最后真实相邻边沿
间隔”，恢复门限原有的取较小值设计；不要直接取消 early 门限、
跨过门限后自动承认早期脉冲，或继续提高启动功率。首次换相延时
也使用了平滑周期，是相邻的待研究问题，不在本轮直接修改。

## 对 S4 两项改动能确认到什么程度

- #8 确实执行了完整六段约 8 ms 试探（45–93 ms），此后获得孤立
  边沿、再超时，最终凑足连续六边沿。不是短试探期间立即成功。
- #17 在约 45.099 ms 进入第一段短试探，46.068 ms 收到有效
  边沿后立刻取消。它发生在此前 22.5 ms 等待也能覆盖的时刻，
  所以单凭这一次不能证明缩短等待带来了改善。
- 本轮没有零边沿未接管，但成功槽的早期事件已覆盖；不能断言
  15 次成功都是短试探救活，也不能独立证明两项改动各自的贡献。
- 两次失败都在接管后约 19 ms 就结束，尚未进入 150–450 ms 的
  下限退出阶段，也没到闭环第 30 边沿。不是上一轮已捕获的
  三十边沿撤下限型失败。此时仍有原 400→360 初期包络。
- 成功样本完整跑过退出阶段，但尾段没有保留完整退出波形，不能
  声称已逐点验证每次实际 duty 的平滑性。
