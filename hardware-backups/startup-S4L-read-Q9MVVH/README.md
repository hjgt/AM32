# S4L 首轮13次启动摘要

2026-10-22，用户确认回零停稳后只读抓取。未复位、停核、写设置或刷写。
本次使用S4L ELF地址，读取前后软件门控、GPIO和TIM1 CCR为零，摘要两次读取一致。
通过已知烧录会话的向量及fdTraceInit局部代码比对，不是全Flash校验。
原始552字节摘要见summary.bin，设置、会话计数和解码结果见capture.json。

- 13次共6次进入闭环后用户回零（5、6、9、10、11、12）；7次未锁定后300ms停止（1、2、3、4、7、8、13）。
- 最后13次：首个合格边沿200.6769ms，总接受6个，但最长连续仅4个；10次获取超时，300.0027ms截止。最终stage为PENDING，只表示等待过零后换向，**不表示已满足六连续边沿的接管条件**。
- 末次峰值滤波电流1.17A，最低7.91V；滤波值不是峰值相电流。
- 失败1：最长连续5个，第五个约297.373ms，未在截止前接管；失败4：最长4个。
- 失败2、3、7、8：无任何合格边沿。因此延长试验不能等同对所有无反馈状态无限拉转。
- 成功5也很晚：首边沿202.985ms，第五边沿290.226ms，最终进入闭环。与末次首边沿时间接近，但无波形/逐事件数据，不能认定轨迹相同。
- 其余成功首边沿67.4–95.7ms，4次无启动超时，1次超时1次。
- 上电会话late_stop=0、stale=0、sample_collisions=0；IRQ最大9.4µs，调度最大迟到17.3µs。原生stuck trip_count=0，不是堵转保护触发。

判断：双矢量候选当前未展示可靠性改善。定位固定占用60ms，300ms总预算未改变，留给原获取过程仅240ms；这是设计权衡，可能截断晚建立反馈的样本。末次连续4个不证明下一步必定成功，也不能说明截止瞬间仍在进展。
可讨论的下一试验是有硬上限的获取预算延长，或仅在截止前确有新鲜连续反馈时给予一次宽限；不能取消总截止。后者需要额外判断最新边沿年龄和当前连续计数，摘要仅有历史最大连续数，不足以代替实时判定。
没有重新启用波形记录，也未修改控制逻辑。定位时长/力度是否充分仍未被这些摘要证明。
